# Проверка Flowline — 2026-11-22

## Итоговая локальная проверка AI/CMD

Ветка: `feature/ai-cmd-blocks`. Конкретный Bash-исполнитель расположен в
`backend/internal/cli/command`; `service/run` отвечает за зависимости, рабочие
деревья, состояния и сохранение результатов.

После интеграции результата и выделения CMD-модуля прошли:

- `GOCACHE=/private/tmp/flowline-go-cache make test`: все 14 Go-пакетов с тестами
  и детектором гонок, все 24 frontend-теста.
- `GOCACHE=/private/tmp/flowline-go-cache make check`: `go vet ./...` и проверка
  синтаксиса JavaScript.
- Из `backend/`: `GOCACHE=/private/tmp/flowline-go-cache go build -o
  /private/tmp/flowline-ai-cmd ./cmd/service`.
- `git diff --check`. Бинарники и кэш сборки находятся вне проекта.

Проверено реальными локальными подпроцессами и временными Git-репозиториями:

- CMD без AI-профилей, несколько команд, переменные, пайпы, отдельные stdout/stderr,
  пустые потоки, ненулевой exit code, errexit/pipefail, лимиты вывода.
- JSON поступает на stdin, скрипт остаётся буквальным кодом. Кавычки, переводы строк
  и shell-подобные входные данные не исполняются и не ломают JSON. Числа сохраняют
  исходную точность, распознаваемые секреты редактируются перед хранением.
- Передача CMD → AI → CMD через тестовый AI-исполнитель, параллельные ветки,
  объединение зависимостей и файлов, ошибки и пропуск зависимых блоков.
- Отмена завершает потомков CMD. Отдельный guardian-тест аварийно завершает helper
  backend и проверяет остановку процессов, включая игнорирующие TERM.
- Стабильные ID и источники выходов, переименование ссылок, неоднозначные ссылки,
  циклы, структурная подстановка только в строковые значения JSON.
- Совместимость прежних типов блоков и исполнения без JSON-входа. Неизменяемые
  снимки запусков, SQLite, миграции, восстановление после открытия БД заново.
- Изоляция Git: исходные staged/dirty/untracked изменения сохраняются,
  конфликты объединения и ошибки доступа явно отражаются в результате.
- HTTP-handler сохраняет и выполняет CMD-пайплайн, отдаёт его через bootstrap,
  отклоняет неверный JSON. Frontend-тесты проверяют реальные обработчики инспектора,
  разные поля AI/CMD, вставку ссылок, валидацию JSON и историю только для чтения.

## Разработка через сам Flowline

Через запущенный пользователем локальный сервер сохранён и выполнен пайплайн
`flowline_ai_cmd_feature` («Flowline: блоки AI и CMD»).
Запуск `155c79dfe747474d8b24b4e596f2c2f4` завершился со статусом `success`.

Оба блока использовали настоящий авторизованный Codex CLI в отдельных worktree:

1. `implement` создал реализацию; Flowline сохранил commit `3d437bb`.
2. `verify` получил именованный результат и изменения первого блока, проверил
   реализацию и исправил два дефекта; Flowline сохранил commit `f9d7fb2`.

Исправления ревью: незавершённый JSON несвязанного блока больше не мешает
переименовать выход; история получает точный `inputJsonText` и не округляет большие
числа средствами JavaScript. Оба дефекта закрыты регрессионными тестами.
Результат пайплайна перенесён в рабочую ветку fast-forward, затем Bash-исполнитель
выделен в свой модуль. Снимок исходного запуска в SQLite при этом не изменялся.

## Границы подтверждённой проверки

- Реальная цепочка новых типов CMD → Codex → CMD подготовлена, но ещё ожидает
  перезапуска backend. Старый процесс на порту 4173 отклоняет новое поле `command`;
  среда агента запрещает отправить ему SIGTERM (`Operation not permitted`).
- Браузерный host недоступен. DOM-фикстуры проверяют обработчики и селекторы,
  но не подтверждают визуальную раскладку или полную семантику браузера.
- Claude и DeepSeek с настоящими аккаунтами в этой проверке не запускались.
  Их протоколы покрыты локальными CLI/HTTP-фикстурами, отсутствующими в рабочем
  registry. Настоящий Codex подтверждён описанным выше запуском разработки.
